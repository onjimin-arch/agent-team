# 목적지 폴더 분류 기준 (PARA 변형)

vault_schema.md(`agent-team/docs/vault_schema.md`)의 폴더 구조 참고. 표준 PARA 방법론 정의를
따른다 — 설계서에 세부 정의가 없어 이 문서가 실질적인 기준이다. 애매하면 억지로 하나를 고르지
말고 `destination_candidates`에 여러 개를 넣어 에스컬레이션되게 한다(SKILL.md 참고).

| 폴더 | 정의 | 판단 힌트 |
|---|---|---|
| `01_Projects` | 끝(완료 조건)이 있는 구체적 작업과 관련된 정보. "언제까지 뭘 끝낸다"가 있으면 여기 | 마감일, 산출물, 특정 이니셔티브 이름이 원문에 있으면 강한 신호 |
| `02_Areas` | 끝이 없고 계속 유지·관리해야 하는 책임 영역 (예: AX 인프라 운영, 경쟁사 모니터링) | "계속", "운영", "관리" 같은 표현, 반복 업무 |
| `03_Resources` | 나중에 참고할 자료성 정보 — 특정 프로젝트/영역에 즉시 귀속되지 않는 배경지식 | 리서치 결과, 튜토리얼, 레퍼런스 문서 |
| `04_Permanent` | 이미 검증되고 반복 참조할 가치가 있다고 판단되는 핵심 지식(Zettelkasten의 permanent note에 가까움) | note-structurer가 처음부터 여기로 보내는 경우는 드물다 — 자동 승격 로직은 아직 없음(설계서 4절 "향후 확장"). 원문 자체가 이미 정제된 핵심 결론이면 여기로 |

## 애매한 경우의 기본값
- Projects vs Areas가 헷갈리면: 완료 시점이 명시돼 있는지로 가른다. 없으면 Areas.
- Resources vs Permanent가 헷갈리면: 이 정보가 이미 결론/검증된 것인지, 아니면 아직 원자료 수준인지로
  가른다. 원자료 그대로면 Resources.
- 그래도 못 정하겠으면 억지로 고르지 말고 후보 2개를 그대로 제출한다 — 에스컬레이션이 정상 동작이다.
