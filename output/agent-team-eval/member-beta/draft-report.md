# Agent Team Framework 오픈소스 비교 평가 보고서

생성자: member-beta | 생성시각: 2026-05-26 | 버전: v1

---

## 요약

5개 GitHub 오픈소스 멀티에이전트 프레임워크와 비교한 결과, 현재 agent-team 프레임워크는
**"범용 도메인 + Config-driven + 배포 통합"** 조합에서 독보적 포지션을 점한다.
핵심 개선 기회는 **병렬 실행 구조 도입(High Priority)**이며, 파일 오너십 명시화는
낮은 비용으로 안정성을 높이는 단기 과제다.

---

## 핵심 인사이트

### 인사이트 1: 우리 프레임워크의 차별점은 "도메인 범용성 + 배포 통합"

비교 대상 5개 레포 중 4개는 소프트웨어 개발 도메인에 특화되어 있다. 우리 프레임워크는
리서치·분석·번역·개발·설계·GitHub 탐색까지 task type으로 수평 확장한다.
또한 Notion/Gmail/Drive 배포를 워크플로우 Phase 5에 내장한 사례는 오픈소스에서
발견되지 않았다. 이 두 가지가 핵심 경쟁 우위다.

### 인사이트 2: 순차 실행이 가장 큰 구조적 약점

`ciscoittech/claude-agent-framework`는 탐색 3~6개 에이전트, 빌드 최대 8개,
리뷰 5개를 병렬 실행하여 3~6× 속도를 달성한다. 현재 프레임워크는 `plan.md`에서
병렬 가능성을 명시해도 실제 실행은 순차적이다. 이 갭이 처리 시간 차이로 직결된다.

### 인사이트 3: 파일 오너십은 텍스트 규칙만으로 충분하지 않다

`lucasbrandao4770/claude-agent-teams`는 에이전트별 편집 가능 파일 목록을 명시적
테이블로 관리하고, 위반 시 자동 차단한다. 우리 프레임워크의 "절대 금지" 조항은
LLM의 판단에 의존한다. 팀이 확장될수록 이 차이는 사고 리스크로 발현된다.

### 인사이트 4: Config-driven 설계는 오픈소스 대비 명확한 우위

`team-config.yaml` 한 파일로 멤버·task type·배포 엔드포인트를 모두 정의하는 방식은,
AGENT.md를 직접 편집해야 하는 대부분의 오픈소스보다 확장성이 높다. 새 멤버 추가 시
config 병합만으로 완결된다는 점은 오늘 작업(member-eta 추가)에서 실제로 검증됐다.

### 인사이트 5: Slack 연동 + 자동 모드는 생태계에서 드문 기능

`[AUTO: slug]` 트리거와 Socket Mode 봇 연동은 비교 대상 레포에서 유사 사례가 없었다.
외부 시스템 트리거 → 무인 워크플로우 실행이 가능한 구조는 차별화된 자산이다.

## 추천 사항

### 단기 (즉시 가능, 낮은 비용)

**1. 파일 오너십 테이블을 CLAUDE.md에 추가**
각 멤버가 쓸 수 있는 경로 패턴을 명시하여 "절대 금지" 텍스트 규칙을 보완한다.

```markdown
| 멤버 | 쓰기 허용 경로 |
|------|--------------|
| member-alpha | WS/member-alpha/** |
| member-beta | WS/member-beta/** |
| member-eta | WS/member-eta/**, /tmp/research/** |
```

**2. plan.md에 병렬 가능 멤버 표시**
이미 일부 plan.md에서 사용 중이나, 명시적 `parallel_group` 필드를 추가하여
Team Lead가 병렬 실행 여부를 문서화하도록 표준화한다.

---

### 중기 (1~2스프린트)

**3. 병렬 실행 구조 설계 (High Priority)**
의존 관계 없는 멤버를 동시에 실행하는 구조 도입. `ciscoittech` 패턴 참고.
`team-config.yaml`에 `execution.parallel_groups` 필드 추가 고려.

**4. Dry-run 모드**
실제 실행 전 plan.md 기반으로 팀 구성·멤버·예상 산출물을 미리보기 출력.
비용·시간 절감 효과.

---

### 장기 (선택적)

**5. 에이전트 자동 생성 검토**
`SYSTEM_GENERATOR_PROMPT.md` 방식으로 새 task type 추가 시 AGENT.md 초안 자동 생성.
현재 수동 방식도 충분히 작동하므로 팀 규모 확장 후 검토.

**6. 멀티하네스 지원**
Claude Code 외 OpenCode 등 타 하네스 지원은 현재 필요 없으나,
`wshobson/agents`의 단일 Markdown 소스 방식을 참고하여 향후 포팅 비용을 줄일 수 있음.
