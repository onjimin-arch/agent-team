# 바로고 AX 관리 시스템 vs 일반 업무관리 시스템 — 비교 및 개선 보고서

## 요약

바로고 AX 통합 관리 시스템은 범용 to-do·프로젝트 관리 툴이 아니라, 부서 R&R 업무를 **리소스 지수(RI = 총투입시간 × 반복성 가중치)** 로 정량화하고 AI 도입 4단계(Quick Win → 표준 자동화 → 자체 데이터 활용 → 복합 시스템)로 우선순위화하여 AX 케이스로 전환·집계하는 **AX 거버넌스 특화 운영 시스템**이다. 7개 범용 경쟁 제품(Notion·Asana·Jira·ClickUp·Monday·Linear·Trello)과 6개 차원으로 대조한 결과, RI 정량화·가치사슬 스윔레인·AI 도입단계 분류·필드 단위 maker-checker 승인 같은 도메인 기능은 범용 PM 도구가 구조적으로 제공하지 못하는 **명백한 white space**(가장 가까운 영역은 별도 카테고리인 프로세스 마이닝)인 반면, 코멘트·알림·간트/캘린더 뷰·커스텀 필드·전역 검색·모바일·익스포트 등 **범용 협업·뷰·UX 기본기에서는 분명한 갭**이 확인되었다.

> **한 줄 포지셔닝:** "범용 PM 툴이 흉내 낼 수 없는 AX 거버넌스 엔진 위에, 범용 협업·뷰·UX 기본기를 보강하면 도입 장벽을 낮추면서 차별화 격차를 더 벌릴 수 있다."

---

## 핵심 인사이트

### (1) 차별 강점 — 범용 툴의 구조적 white space

| 강점 | 내용 | 경쟁 비교 근거 |
|---|---|---|
| RI 기반 자동 우선순위화 | 투입시간 × 반복성을 결정론적으로 계산해 "어디부터 자동화할지"를 데이터로 답함 | 자동화 ROI·우선순위 산정은 **일반 PM 도구의 네이티브 기능이 아님**. 가장 가까운 영역은 별도 카테고리인 **프로세스 마이닝**(IBM Process Mining 등). 범용 툴은 기껏해야 시간추적 + 대시보드 수준 [gamma §인접영역] |
| AI 도입 4단계 분류 + 단일 업무 LLM 재분석 | 업무를 Quick Win~복합시스템으로 자동 분류, 케이스별 솔루션·도구·난이도를 LLM이 생성 | 경쟁 제품 모두 2025~2026에 "AI 에이전트" 단계로 진입(Notion Agents·Asana AI Studio·Jira Rovo·Linear Agent 등)했으나, **AX 도입단계 같은 도메인 특화 분류는 없음** [gamma §11] |
| 가치사슬 스윔레인 ↔ 업무 리스트 양방향 동기화 | Track→Stage 도식·드래그 편집이 업무 분류 필터와 즉시 연동 | 가치사슬 시각화는 **범용 PM 도구 표준 기능 아님** [gamma §인접영역] |
| 필드 단위 maker-checker 승인 워크플로우 | KPI 정량필드만 승인 게이트, 원본 불변·미승인 배지 미리보기, 본인 요청 자기승인 차단 | 네이티브 결재형 approval은 **Asana(태스크 approval)·Jira Service Management(워크플로우 approval step, 단 커스텀 필드 사전 설정 필요)만**. Notion·Linear·Trello는 버튼/상태/Power-Up 조합이며, 어느 제품도 **필드 단위** 승인은 제공하지 않음 [gamma §6] |
| 부서 자체평가 보고서 + 자동 KPI 스냅샷 + 대표 열람 라인 | 경영 보고 흐름이 제품에 내장 | 범용 툴은 문서 기능으로 수동 작성에 의존 [alpha 차원4] |

→ 차원 4(AX 도메인 특화)는 이 앱의 **존재 이유이자 경쟁 우위**다. 이 영역을 "경쟁 도구도 한다"고 기술하면 부정확하다.

### (2) 범용 기능 갭 — 협업·데이터모델·통합

| 갭 | 현재 상태 | 이 기능을 제공하는 경쟁 시스템(정확 표기) |
|---|---|---|
| 코멘트·멘션·활동 피드 부재 | 없음 (맥락 대화가 Slack에 산발) | 7개 제품 모두 네이티브 지원(보편 기능) [gamma §5] |
| 인앱 알림 센터 부재 | 배지 카운트뿐 | 7개 제품 모두 인앱 알림 지원 [gamma §5] |
| 타임라인/간트·캘린더 뷰 부재 | 없음 | 간트/타임라인: Asana·ClickUp·Monday·Jira·Notion(타임라인). **Linear는 Timeline(로드맵)만이며 캘린더·간트 네이티브 미제공**. **Trello는 Premium 뷰·Power-Up** [gamma §1] |
| 커스텀 필드(사용자 정의) 불가 | 고정 도메인 스키마 | Notion(Relation·Rollup 네이티브)·ClickUp(AI 필드)·Monday(다양 컬럼). **Trello는 Power-Up** [gamma §3] |
| No-code 자동화 룰 빌더 부재 | 없음 | 7개 제품 모두 자동화 지원(Asana Rules·Monday Automations·Trello Butler 등) [gamma §4] |
| 데이터 익스포트(CSV/PDF/Excel) 부재 | 임포트만 강함 | 범용 제품 표준 [alpha 차원6] |
| 외부 Webhook/자동화 트리거 부재 | 없음 | Notion(2025.12 webhook)·Monday·ClickUp·Zapier 연계 [gamma §4] |
| 첨부파일·증빙 관리 부재 | 없음 | 7개 제품 모두 지원 [alpha G12] |

### (3) UX 갭 — 검색·반응형·접근성

| 갭 | 현재 상태 | 경쟁 비교 근거 |
|---|---|---|
| 전역 검색/커맨드 팔레트 부재 | "현재 뷰 업무명" 검색만 | Linear·Notion의 Cmd+K 커맨드 팔레트가 표준 [alpha 차원5] |
| 사용자 정의 저장 뷰·필터 빌더 미완 | 4개 프리셋 탭, "뷰 추가"는 데모 | Notion·Linear(Custom Views)·Monday 모두 필터·정렬·그룹을 뷰로 저장 [gamma §2] |
| 모바일/반응형·전용 앱 부재 | 데스크톱 고정(240px 사이드바·880px 모달) | 7개 제품 모두 모바일 앱 보유. **Asana는 모바일 in-app 승인/거절 지원** [gamma §10] |
| 접근성(키보드·ARIA) 미흡 | div 기반 클릭 | 경쟁 제품도 1차 공개자료(WCAG/VPAT)가 빈약 — **단정 금지**, "각 사 VPAT 확인 필요" 수준 [gamma §10] |
| 사용자 정의 대시보드 위젯 부재 | KPI 코드 고정 | Monday(위젯 50+)·ClickUp·Asana 위젯 빌더 [gamma §7] |

## 추천 사항

개선 로드맵은 **단기(Quick Win) / 중기 / 장기**로 구분한다. 각 항목은 `[근거 → 갭 → 조치 → 기대효과]`로 추적 가능하다. 마지막에 **도메인 특화 강화(격차 벌리기)** 제안을 별도로 둔다.

### A. 단기 (Quick Win) — 저비용·고체감, 기존 엔진 재활용

| 항목 | 근거(경쟁) | 갭 | 조치 | 기대효과 |
|---|---|---|---|---|
| 코멘트·멘션·활동 피드 | 7개 제품 모두 네이티브 [gamma §5] | G1 협업 | 케이스·승인 카드에 스레드 코멘트 + @멘션, AuditLog와 통합 표시 | 부서↔AX팀 의사결정 이력 일원화, maker-checker 맥락 보존 |
| 인앱 알림 센터 | 7개 제품 모두 [gamma §5] | G6 협업 | 승인 요청/처리·AX 단계 전환을 당사자에게 통지(인앱 + 기존 Slack 재활용) | maker-checker 루프 완결, 응답 지연 감소 |
| 사용자 정의 저장 뷰 + 필터 빌더 완성 | Notion·Linear·Monday [gamma §2] | G5 정보구조 | 이미 보유한 6종 그룹핑 엔진 위에 "뷰 추가" 실구현, 다중조건 필터 패널 활성화 | 부서·역할별 작업 흐름 대응, 저비용 확장 |
| 데이터 익스포트(Excel/CSV/PDF) | 범용 표준 [alpha 차원6] | G9 통합 | 테이블·KPI·AX 보고서 PDF/엑셀 출력 | 경영 보고·외부 공유 즉시 가능 |

### B. 중기 — 프로젝트성 가치·증빙 흐름 보강

| 항목 | 근거(경쟁) | 갭 | 조치 | 기대효과 |
|---|---|---|---|---|
| 타임라인/로드맵 뷰 | Asana·ClickUp·Monday·Jira(Linear는 Timeline만, 간트 X) [gamma §1] | G2 정보구조 | AX 케이스의 진척율·기간·도입단계·난이도를 시간축 로드맵으로 표시 | 자동화 로드맵의 경영 보고 가치 급상승 |
| 첨부파일·증빙 관리 | 7개 제품 모두 [alpha G12] | G12 협업/데이터 | AX 계획·완료 증빙(스크린샷·산출물) 케이스 연결 | 보상/정산 케이스 근거자료 확보, 감사 대응 강화 |
| 전역 검색/커맨드 팔레트 | Linear·Notion Cmd+K [alpha 차원5] | G7 UX | 케이스 코드·분류·담당자 횡단 검색 | 부서·업무 수 증가 시 탐색성 유지 |
| No-code 자동화 룰(도메인 최소 트리거셋) | Asana·Monday·ClickUp·Trello Butler [gamma §4] | G4 워크플로우 | "stage=완료 시 절감률 입력 요구", "RI 임계 초과 시 AX후보 자동 제안" 등 도메인 룰부터 | 운영 일관성 + 도메인 차별 자동화 |
| 사용자 정의 대시보드 위젯 | Monday·ClickUp [gamma §7] | G13 통합 | 트랙별 절감·도입단계별 ROI 등 지표 조합을 경영진이 직접 구성 | 보고 유연성, 경영진 채택률↑ |

### C. 장기 — 도입 장벽·확장성 해소

| 항목 | 근거(경쟁) | 갭 | 조치 | 기대효과 |
|---|---|---|---|---|
| 모바일/반응형 레이아웃 | 7개 제품, Asana 모바일 승인 [gamma §10] | G8 UX | 사이드바·모달 반응형화, 모바일 승인·상태 확인 | 현장 운영 인력 채택률↑, 도입 장벽↓ |
| 외부 Webhook/자동화 트리거 | Notion·Monday·ClickUp·Zapier [gamma §4] | G10 통합 | KPI 변경·AX 완료 시 외부 시스템 트리거 | 전사 시스템 연계 확장 |
| 접근성(키보드·ARIA) 개선 | 단정 불가, 모범사례 적용 [gamma §10] | G11 UX | 시맨틱 마크업·키보드 내비·ARIA 적용 | 공공·대기업 도입 요건 충족 |
| 커스텀 메타 필드(제한적 도입) | Notion·ClickUp·Monday [gamma §3] | G3 데이터모델 | **주의: 전면 허용 금지.** RI/KPI 계산 근간을 흔들지 않도록 "계산 비참여 메타 필드"로만 제한 도입 | 유연성 일부 확보, 도메인 정합성 유지 |

> **도메인 정합성 가드레일:** 커스텀 필드(G3)는 임팩트는 크나 고정 도메인 스키마가 RI·KPI 계산의 근간이다. 사용자가 추가하는 필드는 **RI/KPI 산식에 참여하지 않는 메타데이터로 한정**하여, 계산 결정론과 전사 집계 정합성을 보호해야 한다.

### D. 도메인 특화 강화 — 격차 벌리기 (경쟁 따라잡기를 넘어)

경쟁 추격뿐 아니라, 범용 툴이 구조적으로 따라올 수 없는 white space를 더 깊게 파는 제안.

| 항목 | 근거(차별 우위) | 조치 | 기대효과 |
|---|---|---|---|
| RI 추세·시뮬레이션(what-if) | 자동화 ROI 산정은 프로세스 마이닝 영역, 범용 PM 부재 [gamma §인접영역] | KPI 스냅샷을 활용해 "이 케이스 자동화 시 절감 추세" what-if 시뮬레이션 | 데이터 기반 AX 의사결정, 프로세스 마이닝급 가치 |
| AI 도입단계 자동 추천 고도화 | 도메인 LLM 재분석은 경쟁 미보유 [gamma §11] | 단일 업무 "✨ AI 분석"을 부서 전체 일괄 재분류·로드맵 자동 제안으로 확장 | AX 기획 공수 절감, 차별화 심화 |
| 가치사슬 병목 → 자동화 후보 자동 연결 | 가치사슬 시각화 자체가 범용 부재 [gamma §인접영역] | 월 300h+ 병목 단계를 RI·AI 도입단계와 연결해 우선 AX 후보로 자동 큐잉 | 병목→자동화 파이프라인 완결 |
| 필드 단위 승인 → 정책 엔진화 | 필드 단위 승인은 어느 경쟁도 미보유 [gamma §6] | 승인 대상 필드·역할·임계값을 룩업 마스터로 정책화 | 거버넌스 정밀도, 규제 대응력 |
