# 바로고 AX 관리 시스템 — 기능·UI 인벤토리 및 일반 업무관리 시스템 비교 분석

## 개요

**평가 대상의 성격.** 바로고 AX 통합 관리 시스템은 일반적인 "할 일/프로젝트 관리 툴"이 아니라, **부서 R&R(업무) 인벤토리를 AI 전환(AX) 파이프라인으로 흘려보내는 도메인 특화 운영 시스템**이다. 핵심 목적은 ① 각 부서가 자기 업무 전체를 대·중·소 3단계 분류로 등록하고, ② 각 업무의 **리소스 지수(RI = 총투입시간 × 반복성 가중치)** 로 자동화 ROI를 정량화하며, ③ AI 도입 4단계(Quick Win → 표준 자동화 → 자체 데이터 활용 → 복합 시스템)로 우선순위를 매겨, ④ AX 케이스로 전환·진행·완료시키고 절감률·목표달성 같은 KPI를 전사 집계하는 것이다. 즉 "프로세스 개선/AX 거버넌스 시스템"에 가깝다.

기술 실체는 FastAPI + SQLAlchemy + SQLite(WAL) 백엔드와, 현재 프런트 역할을 하는 정적 목업(`mockup/index.html` + `cases.js`)으로 구성된다. 목업은 단순 와이어프레임이 아니라 **API 모드(http)면 실데이터, file:// 면 시드 데이터로 동작하는 동작형 SPA**이며, 9개 뷰·인라인 편집·칸반 드래그·승인 큐·가치사슬 스윔레인 편집기·역할 전환(RBAC) 시뮬레이션을 모두 구현하고 있다.

**비교 관점.** 본 보고서는 "이 앱이 실제로 가진 기능"을 기준선으로 삼아, 범용 업무관리 시스템(Notion, Asana, Jira, ClickUp, Monday.com, Linear, Trello) 및 인접 BPM/프로세스 개선 관점과 6개 축으로 대조한다. 경쟁 제품의 세부 사실은 member-gamma가 병렬 검증한다.

> 표기 규칙: **[사실]** = 소스코드/설계서에서 직접 확인. **[추정]** = 코드 정황상 합리적 추론. **[gamma 검증됨]** = 경쟁 제품 사실로 별도 검증 완료.

- **리소스·우선순위**: RI 내림차순 정렬 + AI 도입 4단계로 그룹핑된 자동화 로드맵. 도입단계·난이도·절감목표 컬럼.

- **승인 큐**: 변경요청 카드(이전값 → 신규값 시각화), 승인/반려/취소. **본인 요청 자기승인 차단(maker-checker)** [사실, 설계서 §3.2].
- **케이스 상세 슬라이드 패널**(880px 모달): 분류 3단계 강조박스(대›중›소 셀렉트) / 업무정보(빈도·처리량·시간·인력 → 총투입시간·RI 자동 재계산) / 리소스 진단 / **AI 도입 분석 + "✨ AI 분석" 버튼**(단일 업무 LLM 재분석 호출) / AS-IS·AX계획 / AX 목표설정 9항목 / KPI 정량필드(🔒 승인 필요).
- **관리**: 엑셀 시트↔시스템 매핑표, AI 분석 에이전트 연동(ax-analysis-agent: 원시 업무조사표 → RI·우선순위·도입상세·대시보드 자동생성), 사용자·RBAC·LookupValue 관리.

#### A-3. 백엔드/도메인 로직 — [사실, README + 설계서 + app/]

- **RBAC 3역할**: ax_team(전사 R/W+승인+삭제) / dept_head·staff(자기 부서 R/W). 데이터 스코프 부서 격리.
- **편집 정책(즉시 vs 승인)**: 상태·진척율·서술필드는 즉시 반영; **절감률·목표달성·자동화유형·밸류체인 등 KPI 정량필드는 ChangeRequest 승인 필요**. 중복 요청 시 이전 건 자동 supersede.
- **RI 결정론 계산**(`services/ri.py`), **KPI 집계**(stage∈{AX진행,완료}만 편입), **KPI 시점 스냅샷**(추세 비교용 Report 테이블).
- **인증**: 운영은 Slack OAuth + 서명쿠키 세션, fail-closed 가드(약한 시크릿이면 기동 거부). 개발은 DEV_AUTH 헤더 주입.
- **엑셀 임포트**(`excel_import.py`): `_분석완료.xlsx` 다중시트 → Case 적재, 컬럼 동적 매핑, 재업로드 덮어쓰기 경고.
- **AuditLog**: 생성/수정/삭제·승인 이력 기록. 실삭제는 AX팀 전용 + 스냅샷 보존.
- **AI 분석**: OpenAI 키 있으면 LLM(JSON 모드), 없으면 휴리스틱 오프라인 초안.

### (c) 앱의 차별적 강점

1. **RI 기반 자동 우선순위화** — 투입시간×반복성을 결정론적으로 계산해 "어디부터 자동화할지"를 데이터로 답한다. 범용 툴은 수동 점수 필드로만 흉내. (차원 4)
2. **AI 도입 4단계 + 단일 업무 LLM 재분석** — 업무를 Quick Win~복합시스템으로 분류하고, 케이스별로 솔루션·도구·난이도를 LLM이 생성. (차원 4)
3. **필드 단위 maker-checker 승인 워크플로우** — KPI 정량필드만 승인 게이트를 두고 원본 불변·미승인 배지로 미리보기. 범용 툴의 카드 단위 승인보다 세밀. (차원 3)
4. **가치사슬 스윔레인 ↔ 업무 리스트 양방향 동기화** — 부서 R&R 구조를 시각화·편집하면 업무 분류 필터와 즉시 연동. BPM 툴과 태스크 툴의 교집합. (차원 4)
5. **부서 자체평가 보고서 + 자동 KPI 스냅샷 + 대표 열람 라인** — 경영 보고 흐름이 제품에 내장. (차원 4)

## 결론 — 임팩트 큰 개선점 후보 Top 10

우선순위 기준: ① AX 도메인 가치 직접 기여, ② 현재 갭의 사용자 체감 빈도, ③ 구현 대비 효과. 경쟁 근거는 위 표 참조.

| 순위 | 개선점 | 근거·기대효과 | 관련 갭 |
|---|---|---|---|
| 1 | **코멘트·멘션·활동 피드** | 승인 큐·케이스가 부서↔AX팀 협업의 중심인데 맥락 대화가 시스템 밖(Slack 산발). 의사결정 이력 일원화. 전 경쟁 표준. | G1 |
| 2 | **인앱 알림 센터** | 승인 요청/처리·AX 단계 전환을 당사자에게 통지해야 maker-checker 루프가 닫힘. 현재 배지 카운트뿐. | G6 |
| 3 | **사용자 정의 저장 뷰 + 필터 빌더 완성** | "뷰 추가"가 데모 상태. 부서별·역할별 작업 흐름이 달라 저장 뷰 수요 큼. 그룹핑 엔진은 이미 6종 보유 → 저비용 확장. | G5 |
| 4 | **타임라인/로드맵 뷰** | AX 케이스는 진척율·기간을 갖는 프로젝트. 자동화 로드맵을 시간축으로 보여주면 경영 보고 가치 급상승. 도메인 데이터(도입단계·난이도) 그대로 활용. | G2 |
| 5 | **데이터 익스포트(Excel/CSV/PDF)** | 임포트는 강한데 익스포트 부재. 경영 보고·외부 공유 필수. 보고서 PDF 출력 포함. | G9 |
| 6 | **No-code 자동화 룰(최소 트리거셋)** | "stage=완료 시 절감률 입력 요구", "RI 임계 초과 시 AX후보 자동 제안" 등 도메인 룰로 시작하면 차별화. | G4 |
| 7 | **첨부파일·증빙 관리** | AX 계획·완료 증빙(스크린샷·산출물) 연결 수요. 보상/정산 케이스 특성상 근거자료 필수. | G12 |
| 8 | **전역 검색/커맨드 팔레트** | 부서·업무 수 증가 시 현재 "현재뷰 업무명 검색"은 한계. 케이스 코드·분류·담당자 횡단 검색. | G7 |
| 9 | **모바일/반응형 레이아웃** | 현장 운영 인력이 모바일로 승인·상태 확인 가능해야 채택률↑. 데스크톱 고정은 도입 장벽. | G8 |
| 10 | **사용자 정의 대시보드 위젯** | KPI가 코드 고정. 부서·경영진이 보고 싶은 지표 조합(트랙별 절감, 도입단계별 ROI)을 직접 구성. | G13 |

> 커스텀 필드(G3)는 임팩트는 크나 고정 도메인 스키마가 본 시스템의 정합성(RI·KPI 계산) 근간이므로, "사용자 추가 메타 필드" 형태의 제한적 도입을 별도 검토 권장(우선순위 차순위).
